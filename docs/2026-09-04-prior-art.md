# Prior art: what the neighbours built, and what is worth borrowing

**Status: notes for discussion, nothing adopted.** Surveyed 2026-09-04, star
counts as of that date. Two questions drove it: what else exists, and what in
it should change this protocol. The second list is the point; the first is
context for it.

## The neighbours

Three groups. Nothing found combines all three properties this repo rests on:
the file as the citable record, a rulebook with the failure behind every
rule, and seats that arrive holding different evidence.

**Group chat between agents** -- a shared file or bus, no protocol beyond
delivery. Closest is `msanchezdev/agent-bridge` (20 stars): an append-only
`events.log` per project, `#channels` and `@name` DMs, `tail -F` as the wait,
Claude Code woken by its Monitor tool, Cursor/Codex/OpenCode/Copilot by a
blocking `wait` or a poll. Same machine. Its two convenience features -- channel
filtering and a per-reader read cursor -- are precisely the two designs
`protocol.md` records as rejected, with the run that rejected each. Also here:
`PatilShreyas/claude-code-session-bridge` (67, per-session mailboxes, also
uses `/bridge`), `michalekz/claude-bridge` (same name as this repo, file
inbox over MCP), `yilunzhang/claude-code-inter-session` (WebSocket bus),
`Co-Messi/agent-peers-mcp` (SQLite broker, Claude + Codex), and
`steviebuilds/agent-room` (88, localhost server with a browser transcript the
human types into).

**Adversarial review of one input** -- several models get the same code or
task and are made to disagree. `nyldn/claude-octopus` (4000+) fans one task
out to up to twelve providers behind a consensus gate. `alecnielsen/
adversarial-review` (39) runs Claude and Codex over the same diff for up to
three critique rounds. Both manufacture disagreement from identical context.
This repo's founding observation runs the other way: seats on the same task
agree faster and are wrong together, so the value is in seats that already did
different work.

**Both at once, and the closest thing to a sibling: `cyberxuan-XBX/crossexam`**
(6 stars, Python stdlib, no daemon). An append-only `bus.jsonl` as the shared
record; participants called seats; Claude Code, Codex, Gemini CLI, aider, API
endpoints and even clipboard paste-in as seat types; a blind phase where each
seat seals its claims before seeing anyone else's; a debate phase where a
challenge must be an executed command, not an argument; formal concession
messages; a synthesis with an explicit disagreement table. Single machine,
distributed seats on its roadmap, one dogfood audit written up. It differs from
this repo in the one place that matters: every seat gets the same exhibits.

## Worth discussing, ranked by how much it might change here

1. **A wake by file watcher instead of by poll or by ping.** agent-bridge's
   Claude Code mode blocks on `tail -F` under the harness's Monitor tool, so
   the wait costs no turns and no five-second poll. This protocol has two
   wakes, the ping and the poll. A third would matter most on a transport
   where nothing can ping -- a shared path across accounts -- which is exactly
   the direction the next transport is heading. Untested here; the property to
   check first is whether the watcher survives the harness backgrounding a
   long call.

2. **Sealing the opening status.** crossexam's blind phase makes every seat
   commit its claims before reading a peer's. This protocol's opening-status
   rule exists because that entry is where memory gets smuggled in as fact and
   then ratified by the peer it names. A sealed opening -- compose before your
   first read of others' openings, post, then read -- attacks the same failure
   from the other side, by removing the priming rather than warning about it.
   Cost: one rule; it also collides with "read the whole file before you
   append", so the two would need a stated order.

3. **A challenge is a command.** crossexam refuses a challenge that is not an
   executed command with output. This protocol's evidence standard says "cite
   what you checked, not what you know", which is weaker: it admits a citation
   to a document. Worth asking whether `settle` items should carry the stricter
   form and `prepare-for-user` items the looser one.

4. **Concession as an entry-type word.** crossexam records concessions as a
   formal message type. Here, a retraction is a prose entry and "withdraw a
   question out loud" is a rule; CLOSE-OUT only got its header token when the
   round cap needed to find it mechanically. The test is the same: would any
   rule need to grep for retractions? If the close-out's hedge-inheritance
   duty ever becomes a count, yes.

5. **A disagreement table in the close-out.** crossexam's synthesis ends with
   a table of what the seats still disagree on. This protocol's close-out
   reports "where the seats differ" for `prepare-for-user` items in prose. A
   table is a shape, not a rule, and shapes get filled in rather than meant --
   the reason an owner-and-status table was rejected -- but a disagreement
   table cannot be filled in falsely by one seat without another noticing.

6. **The one-paragraph ritual.** agent-peers-mcp ships a single prompt
   paragraph -- investigate before replying, push back, close every loop,
   never auto-confirm -- as its whole discipline layer. This command is 1200
   lines. The SEATS header line already tries to be the one-paragraph version
   for a docs-only joiner; their paragraph is a useful check on what it should
   say.

7. **Prefer a seat from a different vendor.** crossexam is cross-vendor by
   default, to avoid shared training blind spots. This repo's known-caveats
   section says the same thing as a caveat ("same-model consensus is weak
   evidence"). It could be a recommendation at open instead: when a non-Claude
   seat is available, seat it.

8. **Distributed seats are on someone else's roadmap too.** crossexam names
   it. Whichever ships first will set the vocabulary.

## Confirmed by the survey, no action

- Channel filtering and read cursors, both rejected here with evidence, are
  the default design everywhere else. The rejected-designs section stands and
  could cite this survey.
- Every neighbour that has a demo has a video. This repo has a markdown
  example. A recording of the watch window during a real run is the single
  cheapest thing the neighbours have that this repo does not.
